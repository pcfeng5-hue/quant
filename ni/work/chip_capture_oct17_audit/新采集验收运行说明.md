# 新采集验收

等待根会话明确告知逐日采集结束后，运行：

```sh
python3 work/chip_capture_oct17_audit/validate_capture.py --prefix full_capture_final
```

脚本不操作浏览器、不联网，不写主库或原始采集目录。只在本独立审计目录生成 JSON 报告、914 日覆盖 CSV、所有原始文件的 SHA-256 清单和独立 SQLite。已有输出不可覆盖；复验时换一个 prefix。

SQLite 含 observations、evidence、metadata、expected_dates。所有记录保留原始 JSON，source_accepted 与 audit_accepted 分开保存，历史研究资格和完整价档状态始终 false。被拒记录仍保存，不把日期错位悄悄修成预期日期。

2026-10-16 已被根会话实际观察，列为额外网页观察目标日。验收分别统计 914 日主库行情基准和 915 日采集目标；CSV 与 SQLite 的 expected_dates 均保留 coverage_scope，扩展日的 main_database_date_present=false。额外网页日不会被判成非法数据，也不代表主库行情已交叉认证或更新。正式脚本增加了独立 OHLC 对照表，限定网页前复权与主库 em_daily_1/adjustment=1 比较；不把主库日期存在当成价格数值已通过，具体结果见正式报告。

脚本检查索引与逐条 record.json 一致、摘要 HTML 与记录值一致、日K HTML 与各字段一致、截图后两种日期一致及 tooltip 可见、日期格式、百分数和成本区间、OHLC、换手率、截图格式及原始证据是否齐全。

采集目录如果在验收期间变化，会标记 source_changed 并非零退出；这种运行是诊断，不能当最终完整性证明。正式报告必须在采集停止后 source_changed=[]，主库前后哈希相同，source_accepted_with_issues=0。

`--limit` 只允许 prefix 含 preview，用于复制出的少量样本检验，不得作为完整覆盖报告。当前 `preview_input/` 是根会话最初两条真实记录的独立副本。第一版 preview 报告有文件列表排序误报，保留作诊断；修正后 `preview_two_real_records_v2` 已通过，正式脚本已修正。

摘要覆盖完成不能称完整逐价档筹码采齐，更不能称已通过无前视偏差验证。
