# A股量化项目 SMART 路线图 v1.0

制定日期：2026年10月7日。目标验收日期：2027年10月7日。

项目定位：为有股票经验、无需自行编程的个人投资者，建立可解释、可复现、有明确风险边界的A股量化决策与交易系统。

现有基础：[资源地图与开发方案](./A股量化资源地图与开发方案.md)。现阶段仅完成资源调研，系统开发、策略验证和实盘验证尚未完成。

## 一、终极目标与 SMART 定义

到2027年10月7日，交付一套用户能够独立通过中文界面完成数据检查、信号查看、回测复核、风险查看和暂停操作的个人A股量化系统；至少一项策略通过事先约定的研究、样本外与前瞻模拟门槛。在券商权限、风险预算与上线条件满足时，完成至少60个实际交易日的小额实盘观察，并通过最终验收。

策略是否有可持续优势不能由项目计划保证。若策略不合格，交付可靠的研究与决策工具，明确标注“交易模型目标未达成”，保持模拟或研究状态；不能把软件完成等同于盈利能力验证完成。

| SMART | 本项目的具体落实 |
|---|---|
| S：具体 | 面向个人A股日线交易；包括数据、1项主策略、回测、模拟、风控、中文界面及有条件的券商执行 |
| M：可衡量 | 每阶段有交付清单；最终检查实验可复现率、风控测试、样本外结果、运行成功率、对账率与用户操作能力 |
| A：可实现 | 优先复用现成组件；首轮研究3个策略假设，最多36次有记录的参数/模型试验；先做日线、单账户和无杠杆研究 |
| R：相关 | 所有功能都服务于选股、仓位、买卖、风险和复盘；每条信号可追溯，每笔订单经过风控 |
| T：有时限 | 2周形成规格；10周交付研究原型与首轮策略评估；6个月完成模拟与上线评审；12个月做最终验收 |

以上是计划基线，不是收益承诺，也不是对现有账户的交易授权。

## 二、时间线与阶段验收

日期是目标评审日，不是自动进入下一阶段的日期。凡交易日样本、账户权限或验收未满足，后续阶段顺延，并记录新日期和原因。

| 阶段 | 时间 | 可交付成果 | 通过条件 | 未通过怎么办 |
|---|---|---|---|---|
| P0 目标与风险规格 | 2026/10/07—10/21 | 交易需求表、风险预算表、数据与券商可行性记录、策略说明模板 | 明确股票池/频率/持仓周期/基准/预算/最大可承受损失；至少3笔用户历史交易转成书面规则；明确哪些主观判断不能可靠量化 | 继续研究原型；未明确实盘风险预算则不进入实盘 |
| P1 数据与回测底座 | 2026/10/22—11/18 | 数据仓库、更新器、1个选定回测引擎、质量报告 | 完成至少30只覆盖正常和特殊情形证券的小样本校验；拟用股票池历史关键字段完整率≥99.5%；严重未解释冲突为0；至少20个核心边界用例全部通过 | 修正数据/撮合；必要时更换数据源或缩小并记录研究范围 |
| P2 策略与中文原型 | 2026/11/19—12/16 | 中文工作台、3个策略假设、统一基线、候选策略评估报告 | 最多36次完整登记的试验；100%试验可追溯；完成时间顺序验证与封存测试；0或1个策略获准进入前瞻模拟 | 无合格策略则记录结论并启动新研究批次，不能硬选冠军 |
| P3 前瞻模拟 | 目标2026/12/17—2027/03/17 | 冻结策略、逐日信号/模拟订单/净值、异常演练与差异报告 | 至少60个真实交易日；至少30个发生交易意图的不同交易日；最近20个交易日无重大技术事故；每日账目可解释率100%；计划任务按时成功率≥99% | 样本不够延长；重大策略改动重新累计前瞻样本，重大系统故障重做受影响观察 |
| P4 半年上线评审 | 目标2027/03/18—04/07 | 数据/模型/软件/券商/风险五项评审、操作手册、应急演练 | P0—P3门槛通过；接入资格明确；实盘本金与人民币最大损失写入配置；用户能独立完成5项关键操作 | 保持模拟；列出具体阻塞项，不能用时间到期代替验收 |
| P5 有限资金实盘试验 | 最早2027/04/08，目标07/07评审 | 独立限额下的小额执行、每日券商对账、实际费用与滑点评估 | 至少60个实盘交易日；最近20日无重大技术事故；每日对账100%完成；无未解释重复订单；未触发未解决的风险事件；实际成本符合预注册容差 | 暂停新增风险、修复/重新验证；亏损不通过追加资金掩盖 |
| P6 稳定化与年度验收 | 目标2027/07/08—10/07 | v1.0系统、策略档案、恢复手册、季度归因和年度评估 | 最近60个计划运行交易日按时成功率≥99%；全部订单有风控和回报记录；关键操作100%可追溯；复现与恢复演练通过；策略仍满足约定风险/表现要求 | 按软件完成、模型未达标分别报告；不为达到“上线”指标放宽标准 |

短期目标：P0—P2，约10周。中期目标：P3—P4，至第6个月。长期目标：P5—P6，至第12个月。

“60个交易日+30个交易意图日”只是最低观察量，不是独立统计样本数量，不证明稳定盈利。不同股票同一天的交易可能高度相关，统计评估应保留这种相关性。若策略本来极低频，应延长观察，而不是增加无意义交易凑数量。

## 三、可实现性与投入假设

本计划假设每周有2—3次开发协作窗口，用户每周投入约60—90分钟：一次需求/策略讨论、一次结果检查。技术工作由助手在实际协作会话中推进；周历不代表助手会在无人交互时自行持续工作。若以后需要定时任务，应另外明确安排。

计划包含约20%的开发返工余量；市场观察期无法通过加班压缩。第一轮数据或券商接入延迟超过7个日历日时，下一次评审重排日期。用户节奏不同则调整日历，不降低技术和风险标准。

第一版范围为日线、股票多头、单账户研究。股票池与调仓频率在P0冻结。高频、融资融券、多账户、复杂深度学习和强化学习不进入第一版关键路径；后续是否增加取决于实际需求和证据。

费用分为数据、执行设备/服务器、模型调用和交易成本。P0分别列明所需服务与月度预算；预算未确定前可以使用允许用途内的免费数据验证，不预设已购买任何服务。

## 四、研究标准：先定义合格，再查看结果

以下是首版建议验收标准，在P0根据真实风险偏好确定。它们是项目门槛，不是行业统一标准。确定后必须在运行策略实验前保存；不能看到结果后放宽。

### 数据和信息时点

1. 目标历史范围：2018/01/01—2026/09/30。若数据覆盖不能满足，先调整数据方案；任何缩短都要披露，不能保持原验证结论。
2. 开发区间建议2018—2021，验证区间2022—2023，最终封存测试区间2024/01/01—2026/09/30。滚动验证在封存区间之外进行，至少3个时间窗口；训练只能使用窗口当时可见的数据。
3. 保留当时股票池、退市证券、ST/停牌状态、公司行动及可获取的历史分类。无法重建历史状态的数据不得用于声称排除了幸存者偏差。
4. 财报按照实际可获取时点及修订版本进入模型。不同来源的发布日期与更新时间要区分。
5. 特征、订单、持仓核算的复权口径分别写入规格；统一中国市场时区。

### 第一轮实验控制

- 先研究3种假设，例如趋势、相对强弱、质量/估值；具体以用户经验和数据可用性为准。
- 每种最多12次参数/模型配置，共36次。策略规则、股票池或特征的改变同样计入试验记录，不能隐藏试错。
- 候选人选定后才打开最终封存测试。测试结果用于接受或拒绝；如果据此修改，该区间成为已知数据，新版本需要新的未使用数据或前瞻观察。
- 评价包含费用后收益、基准差异、最大回撤、换手、行业/市值暴露、参数敏感性和成本压力。

### 候选策略晋级标准（研究提案）

先在P0选择与股票池和风险敞口匹配的总回报基准，并同时报告原始基准和按策略风险配置的对照；避免通过降低仓位简单宣称优于满仓指数。

| 指标 | 提案门槛 | 含义 |
|---|---|---|
| 净收益 | 封存测试期累计净收益>0，且相对预定风险匹配基准的累计差异>0 | 提供最基本的候选优势证据，不推导未来年化收益 |
| 回撤 | 封存测试最大回撤≤10% | 暂定研究筛选目标，P0按用户风险偏好冻结；不是未来损失上限保证 |
| 成本压力 | 佣金、税费按适用时间处理，基准滑点假设×2后累计净收益仍>0 | 检查对执行误差的脆弱性，费用基准需来源支持 |
| 时间稳定性 | 至少3个滚动验证窗口，其中至少2个费用后收益>0且优于预定对照 | 最低诊断门槛；仍须完整披露所有窗口 |
| 参数稳定性 | 对主要参数做预先定义的±20%邻域检查，至少70%邻域配置费用后累计收益>0 | 减少只在某个尖锐参数点表现好的候选；这些配置也纳入试验记录和多重试验评估 |
| 不确定性 | 报告保留时序相关性的重采样区间、试验总数与选择偏差说明 | 若优势证据不清楚，继续模拟；不把一个漂亮夏普比率当作定论 |

36次限制包括邻域试验，研究开始前分配名额。若预算耗尽，则形成该批次结论，新批次必须登记，不能重置累计试验数掩盖多重选择。

前瞻模拟评审还需要：同期费用后累计收益为正且相对预定对照为正、未突破冻结的风险门槛、与回测差异有可解释记录。若短期结果不清楚则延长，不通过修改既定比较口径获得通过。

## 五、风险体系与触发动作

风控阈值可以降低风险，但跳空、连续跌停、停牌、流动性或系统故障可能导致损失超过阈值。因此“触发暂停”与“保证在某价格卖出”是不同事情。

以下数值仅用于研究/模拟的初始设计，正式风险规格应在2026年10月21日前确定。没有用户的实盘本金、可承受人民币损失和账户约束，不把这些值直接部署到账户。

| 项目 | 初始研究/模拟提案 | 控制方式 |
|---|---|---|
| 杠杆 | 0融资、0融券 | 首版拒绝增加杠杆的指令 |
| 总股票仓位 | 下单后预计不超过策略净值60% | 对新增风险订单做事前检查；市值变化造成越界则报警并评估调整 |
| 单股仓位 | 下单后预计不超过策略净值10% | 订单校验，按实际交易单位取整 |
| 行业仓位 | 下单后预计不超过策略净值25% | 行业映射与持仓聚合校验 |
| 策略净值回撤5% | 黄色预警 | 展示归因，停止提高风险预算 |
| 策略净值回撤8% | 暂停新增风险 | 允许按既定规则做减险和对账；人工复核数据、市场与模型 |
| 研究回撤10% | 候选策略不合格 | 返回研究；不得靠重置净值或入金清除记录 |
| 行情过期、关键字段缺失、持仓不符 | 阻止受影响的新增订单 | 展示原因并要求恢复后校验 |
| 超时或订单状态不明 | 查询与对账 | 不盲目重发，避免重复下单 |

净值按策略专属账簿、扣除费用并剔除出入金影响计算；回撤基于连续净值高水位，不因更换策略名字或软件版本自动清零。另保留项目实盘累计盈亏与人民币损失预算。既有手工持仓在混合账户中必须可区分，否则不自动执行。

实盘前要锁定：试验本金C、最大可承受人民币损失L、账户隔离方式、订单限额、日内异常损失阈值、成本容差及恢复权限。C、L由用户决定，不默认调用全部股票资产。

放大资金没有固定日期：至少完成P5观察、费用与流动性可承受、风险门槛仍满足，并重新确定预算后才讨论。恢复交易也需要完成故障或策略评审，不因等待若干天自动恢复。

## 六、工程验收与指标口径

| 指标 | 定义与目标 |
|---|---|
| 关键数据完整率 | 满足预定可交易条件的“证券×交易日”必需记录齐全数/应有数≥99.5%；合法停牌等按规格处理，不以删除缺失证券抬高比率 |
| 严重数据差异 | 会改变信号、价格口径或现金持仓计算的未解释差异=0；抽检范围与容差在检查前固定 |
| 可复现率 | 固定代码、参数和数据快照，同一实验重复3次；订单清单与信号一致，金额差异在预先定义的舍入容差内；合格率100% |
| 核心边界测试 | 至少20项全部通过，覆盖可卖数量、涨跌停、停牌、交易单位、复权、费用、现金、重复信号、回调重复/乱序、断线/超时、恢复和对账 |
| 按时成功率 | 预定截止时点前，数据验证与日报/信号任务均成功的交易日数/全部计划交易日数；目标≥99%，中断与外部故障计入，不从分母删除 |
| 截止时间 | 日线初始建议交易日北京时间21:00；P0按数据服务更新承诺冻结，晚到数据必须显式标记并阻止过期交易 |
| 对账率 | 应对账日中完成现金、持仓、订单和成交核对的天数/全部应对账天数=100%；未解释差异阻断新增风险 |
| 风控覆盖 | 100%订单经过独立风控，保存通过或拒绝原因；拒绝也进入审计日志 |
| 故障检测 | 执行服务运行时，心跳丢失在60秒内触发监控；需外部监控端才能发现整机离线，故障注入演练验证 |
| 恢复能力 | 备份恢复演练在60分钟内完成；交易事件持久化，重启后先与券商补查对账，不能声称所有断电情形零数据丢失 |
| 易用性 | 用户不写代码，独立完成更新数据、查看信号理由、查看风险、暂停新增订单、导出报告5项任务，每项≤5分钟 |

重大技术事故指错误/重复/越权订单、关键账目不明、错误数据触发交易、风控被绕过或关键服务无告警失效。对这些事故不以“总成功率还很高”为由放行。

## 七、分工与执行节奏

| 事项 | 助手负责 | 用户负责 |
|---|---|---|
| 需求 | 把交易语言变成规格，指出模糊条件 | 提供交易经验、反例、持仓习惯与风险底线 |
| 技术 | 选型、编码、测试、文档和故障排查 | 必要的本机安装操作或账户端开通 |
| 研究 | 数据审计、实验登记、偏差检查和结果解释 | 判断规则是否符合真实交易逻辑，不只看收益曲线 |
| 资金 | 实现预算检查与日志 | 确定本金、人民币损失预算及上线/增资选择 |
| 验收 | 出具证据、缺陷及未达标项 | 检查中文操作流程是否可用，参与关键评审 |

每周一次简短复盘：本周完成什么、有哪些证据、发现什么风险、下周唯一主目标。每两周形成一个可演示版本；每月评审范围和进度。遇到关键质量问题，先修复，暂停新功能扩张。

这一节规定协作节奏，没有创建提醒或自动化任务。

这些日期建立在持续协作和访问条件可用的假设上；若用户暂时无法提供账户信息，可继续研究工作，但不得把未知接入条件标为通过。

## 九、年度验收清单

- 软件：中文工作台可用；代码、参数、数据和运行环境可复现。
- 研究：至少一项策略通过冻结的筛选标准和未被反复调参污染的样本外/前瞻评估；所有失败批次留档。
- 风控：所有订单经过校验；暂停功能及至少20项异常/边界用例通过；本金与人民币损失预算明确。
- 运维：最近60个计划运行交易日按时成功率≥99%；每日对账100%；恢复演练通过。
- 实盘：若获准开展，至少60个实际交易日的订单、费用和持仓记录完整，风险和成本评估合格。未开展或未达标则明确报告实盘目标尚未完成。
- 用户：无需写代码完成5项关键操作，能解释当前策略何时交易、何时不交易、何时暂停。

验收结果分为“软件合格”“研究候选合格”“模拟合格”“有限实盘合格”，逐项记录。全年收益不是必达数字，不用承诺年化收益替代专业验收。
