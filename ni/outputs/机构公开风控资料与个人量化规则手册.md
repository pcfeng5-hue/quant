## 1. 核心结论

可以借鉴机构的风险预算、分层限额、独立检查、压力测试、异常处置和模型验证方法。不能把银行资本监管比例、机构自营组合参数或海外法规直接当成个人A股账户规则。

第一版应采用“策略提出交易意图 → 独立风控放行或拒绝 → 执行 → 回报对账”的架构。用户已描述的提前买入、回落重仓买回、不愿空仓，由明确策略条件与仓位控制共同处理。机构风控资料不能替我们证明哪一个买点有效。

本文区分三类依据：U为用户已确认要求，S为公开来源中的机构方法或监管要求，P为我们为研究/模拟提出的参数与实现选择。P不冒充投行内部规则，不自动成为实盘设置。

## 5. 三个具体场景

### 场景A：盈利卖出后，价格回落，想买2万元

系统先检查新的入场条件。若不完整，直接拒绝并显示缺项。即使信号完整，研究提案的首次开仓上限约2,500元也会拦截2万元订单。不能把它拆成8笔规避；订单累计预留受同一个限额约束。

### 场景B：觉得跌得够多，但没有经过验证的入场信号

显示“没有合格信号，继续观察”，不为满足交易次数而生成订单。市场环境过滤条件必须写成可计算表达式并验证，不能以“趋势不好”作为无法检验的标签。

日线策略如使用当日收盘数据，最早在这些数据实际可获得之后的合法交易时段执行，不能回测成事先知道收盘价并按同价买入。具体执行时段、报价边界和有效期在策略规则卡中冻结。

### 场景C：两只股票名称不同，但同时受同一主题影响

系统同时检查单股限额和风险组总额。两笔持仓各自不超限，不代表组合风险已分散。是否属于同组，依据历史时点可知的行业/主题映射和相关性检查；不未经核实就给用户提到的两只股票归类。

## 6. 仓位计算：金额上限与损失预算取较小值

仅作为实现示例：

允许新仓金额 = min(首次开仓余额, 单股额度余额, 风险组额度余额, 总仓位额度余额, 可用现金减预计费用, 计划损失预算对应金额)。

若采用价格失效点：数量q须同时满足 q×(预计买价−失效参考价)+预计交易成本(q)+滑点缓冲(q)≤单笔计划损失预算，且符合交易单位及金额限额。每次调整数量后重新计算费用，不能忽略最低佣金。不能满足最低合法数量就不交易。

该计算只是计划情景。买入当日不可卖、隔夜跳空、跌停无成交等情况会使实际损失超过计划预算，必须补做压力测试。止损价也不等于确定成交价。

## 7. 压力测试与准入条件

参考S01/S02的多情景方法，以下冲击幅度为P假设，不是概率预测、交易所涨跌幅或投行内部参数。

| 场景 | 测试输入 | 在5万元示例账户中的直观结果 |
|---|---|---|
| 市场共跌 | 3万元股票敞口同时下跌15% | 静态损失约4,500元，未计费用 |
| 单股跳跌 | 5,000元单股敞口下跌20% | 静态损失约1,000元，不能认为250元计划风险必然封顶 |
| 主题集中 | 1万元主题组同时下跌30% | 静态损失约3,000元 |
| 无法退出 | 受影响标的连续数个交易日无法成交 | 保留持仓并按情景重估，不能假设达到止损线即卖出 |
| 成本变差 | 基准滑点提高至2倍、成交量下降 | 重算费用后收益和退出时间；基准滑点先用数据校准 |
| 执行故障 | 下单成功但回报丢失、撤单后仍部分成交、Mac断网 | 不重复提交；重连查询后恢复账簿 |

前三项是独立示例，若持仓重叠不能直接相加；组合情景逐证券重估。应配置压力损失上限后再决定是否允许新单，本文不把1万元用户暂停阈值自动当作所有压力情景的合格线。

VaR可作为后续诊断工具，第一版不以它作为唯一放行依据：估计值受数据和假设影响，不是最坏损失或止损保证。小账户先保证账簿、集中度、现金和情景计算正确。

## 8. 实现验收与运行日报

开发时至少为C01—C20各设计一个触发案例，边界用例另外覆盖“刚好等于阈值、差一个最小单位、并发、重启、撤单未确认”。验收要求：所有应拦截案例100%拦截，无重复订单；同一快照重跑决定一致。

日报至少显示：

- 策略净值、已实现/未实现损益、初始本金亏损、高水位回撤。
- 已持仓与未成交买单预留合计，单股/主题/组合限额占用。
- 每条买入意图通过或拒绝的理由；当日无交易也形成报告。
- 费用、滑点、对账差异、报价质量及运行异常。
- 压力情景结果、模型/规则版本、当前暂停原因和恢复所需证据。

暂停状态区分：数据暂停、订单状态暂停、资金风险暂停、模型暂停、人工停止。程序重启后恢复原暂停状态；操作界面不会因重启显示“正常”。

风险触发后的恢复顺序：确认现金/持仓/在途单 → 定位原因 → 修复或保持减险状态 → 重跑相关测试 → 记录恢复决定。风险预算上调与故障恢复分开，不以增加资金或放宽限额掩盖失败。

## 9. 与项目计划的衔接

本轮完成公开资料到规则规格的映射，没有实现风控引擎。接下来在P0形成策略规则卡和风险配置草案，在P1对上述控制进行合成场景测试，在P2—P3验证策略与风控组合效果。

现在无需用户背诵投行规则或额外购买报告。需要用户最终确认的是风险参数、操作体验和遇到拦截时愿意遵守的变更流程；买点是否有效由后续研究提供证据。

## 10. v0.2：漏洞审查与精化

本节是项目工程设计，不是新增机构原文要求。来源方法仍为S03—S08。风险改进的单位是“发现的缺陷、修订的规则、验证证据”，不是新增规则数量或不断调低比例。

### 10.1 已识别缺口及修订

| 缺口 | 修订后的明确规则 | 必须证明的情景 |
|---|---|---|
| 首次买入限额可能被多个订单绕过 | 首次开仓额度按交易决策/持仓周期归集；所有拆单共享额度。首轮禁止加仓版本只允许完成原已批准目标数量，不新增目标 | 一个2500元意图拆单不能变成多次2500元；部分成交重报只补剩余合法数量 |
| “有唯一编号”仍可能重复买入 | 决策键绑定账户、策略版本、证券、决策时点和动作；生成新订单编号不能逃过意图去重。意图和额度预留先持久化再发送 | 发单后崩溃、提交超时、重复点击、重复信号均不产生第二个完整意图 |
| 撤单确认与成交回报可能乱序 | 额度从预留转为持仓占用，不能双算或漏算；成交按券商成交唯一标识去重。状态不明保留保守预留，查询确认后更新 | 撤单回报先到、成交回报后到；部分成交后余量撤销；重启后回补 |
| 多个策略同时检查后都可能超限 | 共享账户风险账簿，校验与预留为一个原子操作；预留状态跨进程和重启有效 | 两笔各自合格的并发订单，合计超限时只能放行可容纳部分意图，另一笔拒绝 |
| 简单净值比例会因反弹自动扩大预算 | 实际限额应同时受净值比例和经确认的绝对金额预算约束；资金增长不自动视为增资授权。具体绝对上限待定 | 净值上涨或入金后，未获新的风险预算不能突然扩大订单 |
| 只看浮亏金额会漏掉盈利回吐 | 分别记录初始本金累计损益、高水位回撤、当日损益和项目总损益。1万元只对应已确认的本金累计亏损暂停线 | 5万涨到6万又回5万时，显示本金损益0与回撤约16.67%，不能显示“没有风险” |
| 损失触线时在途买单仍可能成交 | 触线立即阻止新增买入，尝试撤销可撤买单；尚未确认撤销的部分继续纳入风险。触线状态锁存 | 暂停期间迟到成交能正确更新敞口并报警，不因暂停而丢弃回报 |
| “减险单”可能成为绕过风控的通道 | 减险订单必须证明对应真实可卖持仓，且不增加其他敞口；仍检查价格、证券身份、数量及重复状态 | 错误方向、超量卖出、错误代码不能以“止损”名义放行 |
| 所有故障一律禁单可能妨碍合法退出 | 区分策略数据故障与执行事实故障。模型特征缺失时可保留基于独立可靠持仓/报价的既定退出；持仓或执行报价不可信时停止自动发单，提示人工通过券商核验 | 数据源故障时既不盲卖，也不静默失去退出管理能力 |
| Mac整机失联时本机无法报警 | 实盘要求独立于执行进程/主机的心跳观察与通知；明确人工响应联系人和处理步骤。未部署不声称已有离线保护 | 进程崩溃、整机断电、网络断开分别测试；离线时无法保证撤单成功 |
| 看似分散但共同下跌 | 行业与主题分别定义；同一证券可计入多个风险组，每组独立检查，但组合资产不重复计值。相关性失效用共同冲击情景补充 | 多主题重叠、标签缺失及压力下相关性趋同 |
| 被动超限和主动越限混淆 | 新订单不得制造主动超限；价格变动造成被动超限则报警、停止增险并按预定再平衡规则处理 | 一只上涨致超限，不自动制造高换手抛售；另一只下跌导致总净值降低同样检查 |
| 人工交易与程序账本分离 | 同账户所有真实订单和持仓纳入账户级限额；策略归属不明时阻止自动增险。无法阻止用户在券商端另行下单 | 手工买入、手工撤单及程序未知持仓能被查询发现并进入对账 |
| 故障恢复与风控放宽混在一起 | 恢复须有原因定位、对账、受影响测试和决定记录；任何阈值放宽走另一个版本流程 | 重启、跨日、价格反弹、换策略名字或入金都不能解除锁存事件 |

### 10.2 规则优先级与状态

同时命中多个限制时，记录全部原因，对新增风险采用最严格结果。系统保存多个暂停原因；一个原因解除不能覆盖其他未解决原因。

优先处理顺序：证券/账户身份与合法约束 → 执行事实可信度 → 人工紧急停止 → 已锁存资金风险 → 额度及集中风险 → 策略信号。顺序不意味着后面的检查可以省略；撤单和查询使用专门路径，不被“禁止新买入”误阻断。

建议状态集合：观察、允许按规则交易、禁止新增风险、执行事实待核对、人工紧急停止。状态变更持久化并带时间、原因、版本；允许交易不等于必须买入。

### 10.3 预算缓冲与参数待定清单

1万元是用户愿意触发暂停复核的累计损失线，不是可以先花掉的风险预算，也不是未来损失上限。

新增交易准入需要同时考察：当前已发生亏损、现有持仓压力损失、未成交订单全部可能成交后的额外压力损失，以及退出受阻的执行缓冲。组合逐证券重估，防止重复计入情景。这里的压力预算上限应单独确定，不直接等同1万元。

上线前必须具体化的参数：高水位回撤预警/暂停线、日内异常损失线、组合压力损失预算、执行流动性/参与率限制、最大价格偏离、报价有效期、报撤单频率、人工响应时限、各项绝对金额限额。任何必需参数为空或来源过期，实盘配置验收失败；研究环境可用明确标注的假设进行测试。

不能为了把计划损失压进250元就任意把止损距离改小。先确定策略失效条件及跳空压力，再计算可承担数量；数量不足最低交易单位则跳过。

### 10.4 三轮精化与退出标准

| 轮次 | 工作 | 可验收结果 |
|---|---|---|
| 定义审查 | 逐项核对金额口径、时点、数据来源、状态、权限与冲突 | 本轮已形成缺口表；待定阈值明确列出，没有默认为通过 |
| 故障验证 | 用合成订单和行情覆盖上述边界，不连接实盘 | 必须拦截的案例全部拦截；无超额度预留、漏记成交和重复意图；不是本轮已完成的测试 |
| 策略效果验证 | 同一批信号比较加/不加某项可选风控的结果 | 报告尾部亏损、回撤、成本、误拦截、错过机会及退出受阻时长；测试集之外冻结参数 |

不参与效果取舍的底线：合法交易约束、真实账簿、重复订单防护、用户明确的限制、权限与数据完整性。需要效果比较的包括仓位比例、环境过滤、冷静期、信号确认次数及退出参数。

通过更严格风控而减少交易，不自动算进步。若尾部损失下降但费用、误拦截或退出失败明显增加，必须披露权衡并重新设计。冻结一版进行验证后再迭代，不能每天按盈亏改变规则。
